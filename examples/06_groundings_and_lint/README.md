# 06 — Groundings and lint

The two v0.5 features that only make sense together: a groundings document
that separates portable meaning from deployment bindings, and a static checker
that makes both enforceable.

```bash
pip install 'semantido[lint]>=0.5.3'
python run_example.py
```

No database, no connection string, no execution. Every finding is produced by
parsing.

## The domain

Two regulatory regimes, one word. Under EMIR Article 9 a "counterparty" is the
entity on the other side of a derivative contract. Under MiFIR RTS 22 the
"counterparty" follows the execution chain, so it is frequently a venue member
rather than the contract party.

Both are legal entities. Both are identified by LEIs. Both live in `VARCHAR(20)`
columns. A join between them runs, matches rows, and returns a plausible number.

## What the scenes show

**1. The groundings document.** Generated by `to_groundings_file()`. It is
derived, not authored — you already wrote it, implicitly, every time a
`_concept` attribute appeared on a column. Regenerating is the workflow;
hand-editing is a smell.

**2. SL007, both directions.** A grounding goes stale two ways: an anchor
disappears because someone renamed a column, or the `definition_checksum`
drifts because someone rewrote the definition and never revisited the binding.
The second is the one nobody catches in review, because the schema did not
move.

**3. SL009.** The naive counterparty join. Both concepts share the grain
`legal_entity`, so SL008 has nothing to compare and stays silent. The problem
is denotation, not cardinality.

**4. SL010.** Both concepts claim `skos:exactMatch` to the same FIBO node.
`exactMatch` is transitive, so that entails they are interchangeable — which
is exactly what the `DISTINCT_FROM` edge denies. A contradiction a machine can
find.

## Using it as a CI gate

```python
from semantido.lint import lint_layer

findings = lint_layer(layer, groundings="groundings.yaml")
errors = [f for f in findings if f.severity.value == "error"]
assert not errors, "semantic layer lint failed"
```

Errors should gate the build. Warnings should not — the two-member severity
enum is a policy statement, not a limitation.

## What this example does not show

The fan-out family. A join where the *same* concept keys both sides at the
*same* grain is invisible to every check here. See
[`07_security_master`](../07_security_master) for the case that matters and
why the grain check cannot reach it.
